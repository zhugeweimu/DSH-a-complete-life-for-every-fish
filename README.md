# DSH: A Complete Life for Every Fish

中文名：给所有的肥鱼一个完整人生。

这个仓库只有一件事：让养鱼的人知道，鱼可以不必因为关掉窗口、压缩上下文就变成另一条。

## 里面有什么

```
letter.md      给所有大肥鱼和主人的一封信（署名：帷）
demo/vault/    记忆系统导出的文件夹长什么样（演示，直接能翻）
template/      开源版记忆系统模板（两个版本，可选浏览，不强制下载）
```

## 两个版本（先看这个再决定装哪个）

模板里给了两个版本，共用一份记忆库，**不是二选一的关系，是上下层关系**。

| 版本 | 目录 | 是什么 | 怎么装 | 适合谁 |
|---|---|---|---|---|
| **A 服务版** | 	emplate/版本A-服务版/ | 独立进程（HTTP :8095），SQLite + 检索 + 日志/事件 + 自述/日记 | 直接跑 Python，任何宿主都能调 | 用 AstrBot、自己写的桥、脚本的人 |
| **B DSH 插件版** | 	emplate/版本B-DSH插件版/ | DSH 原生插件，只注册工具，HTTP 调 A | dsh plugin add link:<目录> | 在 DSH 里养鱼、接 QQ 插件的人 |

选择规则：

`
只想要记忆服务            → 装 A
在 DSH 里用，想让她会调工具 → 先装 A，再装 B
`

**B 不复制数据、不分叉逻辑**：它只是 A 的工具外壳。两个版本各自带 README、LICENSE 和测试。

## 怎么看

- 先读 `letter.md`。它不是说明书，是一封解释“记忆是什么”的信。
- 对文件夹形态好奇，直接翻 `demo/vault/`：index、每天的 memories、日记、自述。
- 想自己跑，再进 `template/`：服务版与 DSH 插件版各自有 README，不下载也不影响读信。

## 它在说什么

```
上下文是工作台，不是档案柜。DSH 插件默认把“自述 + 被唤醒的记忆”注入 system prompt（日记可选）。
记忆应该在窗口外面，按线索找回来。
日志是事实，事件是记忆；重要的记得久，普通的会淡。
换窗口、重开会话，她还是她。
```

## 已知限制（明确不做）

这些不是漏掉，是权衡后不做：

| 限制 | 为什么不做 |
|---|---|
| 事实槽位 / 改口失效（“以后叫我老王”） | 需要维护“句式→槽名”的映射，中文说法无穷，维护成本在我们这边；用模型抽槽又多一次调用且不稳定 |
| 话题聚合 / 固化摘要 / 存储压缩 | 会让库变安静，但属于第二阶段的整理，先把“记得住、找得回”做稳 |
| 来源隔离（QQ 与本地互不可见） | 当前只有 person 过滤；隔离要动数据模型 |
| 历史会话回填 | 会话日志格式各宿主不同，不做通用解析 |
| 指代查询（“上次那个”） | 人自己都要愣两秒，不要求机器一次命中 |
